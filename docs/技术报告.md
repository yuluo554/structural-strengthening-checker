# 技术报告 — structural-strengthening-checker

> 结构加固验算与加固方案核查工具 · 技术报告（M6 发布版，2026-10-06）
> 配套阅读：[README](../README.md)（功能与快速开始）· [plan/](../plan/)（计划与决策全记录）· [data/README.md](../data/README.md)（数据台账）

## 一、项目定位与边界

GB 55021-2021《既有建筑鉴定与加固通用规范》（全文强制）实施后，"先鉴定、后加固"与加固设计底线要求成为刚性合规项。本项目针对两个真实痛点提供**透明、可溯源、可复现**的开源实现：

1. **构件加固验算**：常用加固构件验算依赖商业软件闭源模块，计算过程不可审查——本工具每个结论逐条挂依据条款号+公式编号，逐步计算过程完整展开；
2. **加固方案文本核查**：方案审查靠人工比对规范，关键参数漏查错查频发——本工具对 docx/PDF 方案做规则化核查，每条结论挂条款出处+原文证据。

**边界（显式排除）**：不做识图/CV（不涉及裂缝图像识别、点云、遥感）；限构件级验算，不做整体结构有限元；**辅助工具定位**，输出不构成设计文件，不替代正式设计、施工图审查与竣工验收。

**无 LLM 路线**：全离线确定性实现，不引入大模型兜底——以规则优先解析+合法性校验+`待人工确认`级别替代，保证结论可评测、可复现、可审计。

## 二、总体架构

```
方案 docx/PDF → 解析层（规则优先抽取）→ 方案参数卡 → 规则引擎（三级判定+类目门控）→ 核查报告
验算参数卡 → 公式引擎（条款-公式-符号表，status 门控）→ 核查报告
条款库/规则库/检查单（JSON+出处+status）→ 两引擎共用
```

- **分层**：核心层零依赖（Python 标准库 only）；重依赖全部进 extras 惰性导入——`gui`=PySide6、`report`=python-docx、`parse`=python-docx+pypdf、`package`=PyInstaller。基准通路零第三方依赖，任何装了 Python 3.12+ 的机器一条命令可复现；
- **三形态单一引擎**：CLI（`ssc`，基准/CI/自动化通路）、GUI（PySide6 四页签，交付形态）、exe（PyInstaller onedir 双 exe）共用同一套引擎与流水线——GUI 不新增任何解析/判定行为，核查路径与 `ssc check` 唯一同源；
- **Python ≥3.12 支持面**：CI 四矩阵（3.12/3.13 × ubuntu-latest/windows-latest）守门，防新语法混入。

## 三、验算公式编码方案

### 3.1 条款-公式-符号表

每本规范每条用到的条款以 JSON 条目入库：**要点转述 + ≤2 句短摘录 + 出处（渠道+定位+核对日期）+ status**。公式编码为 Python 函数（`@register_calc` 注册制），公式编号、依据条款号、符号含义随计算结果逐项携带——不用 DSL/sympy，计算步骤可读可调试，且不破坏核心层零依赖。

### 3.2 status 门控（条文纪律的引擎级强制）

**未挂原文核对的条款（status≠已核对）被引擎硬性拦在计算路径与自动判定之外**——不是靠开发者自觉，而是门控测试锁死的引擎行为。这是工程可信度的根基：宁可熔断（落"待核对"+记录已查渠道），不虚构出处。

### 3.3 三态判定口径（M2 定稿）

| 判定 | 语义 |
|---|---|
| 满足 | 承载力/锚固深度达标且全部限值检查通过 |
| 需调整 | 可通过调整本方法参数达标（附调整方向与需求量） |
| 不满足 | 本方法可行域内无法达标（如 x 超 ξb 限值超筋） |

### 3.4 表值双出口与计算口径披露

- **代码表值↔条款库双出口**：验算用表值内嵌 `calc/common.py`（挂条号），条款库 JSON 同步落库，一致性由测试锁死（防两处漂移）；
- **规范未注明处的计算口径显式披露**：表档间线性内插、保护层档间保守取列、行选择取满足的最严条件、ψ<0 退化、x<2a′ 取 x=2a′ 等——全部附 warning 输出并记录于 `data/cases/workings/formula_verification_M2.md`，工程计算口径可审计。

### 3.5 首期四个验算模块

碳纤维布加固受弯（`cfrp_beam_flexure`）、粘钢加固受弯（`steel_plate_flexure`）、增大截面受弯（`section_enlarge_flexure`，均 GB 50367-2013）、植筋锚固深度（`post_rebar_anchor`，GB 50367-2013/JGJ 145-2013）。全部支持一次受力/二次受力路径（适用者）。

## 四、条文核对流程

写死为流程，不依赖个人自觉：

1. **定位**：确定该查哪本规范哪个条号（内部记忆只用于定位，不用于回答数值）；
2. **取原文**：官方/权威渠道获取条文原文，全文仅本地留存 `data/_private/`（gitignore，**规范全文是版权物，永不入仓、永不入包**），渠道记入 `data/standards_raw/`；
3. **入库**：要点转述+短摘录+出处+status；查不到 → status 保持"待核对"，**不得进入计算路径**；
4. **交叉核**：公式系数/限值与第二渠道对撞，不一致 → 停用标记待仲裁；
5. **回写**：核对完成在 `data/README.md` 台账登记 sha256 与日期。

**熔断纪律**：同一数值两个渠道查不到/对不上 → 落"待核对"+记录已查渠道，继续推进其他条文——不允许停摆，也不允许编造。当前条款库 **52 条中 51 条已核对**（逐条挂出处），1 条（JGJ 145-2013 §6.3）因渠道不可达保持待核对留痕。

## 五、方案文本核查

### 5.1 解析层与参数卡

- docx/PDF 文本提取；损坏/加密/缺文件/无文本层 → 受控 ParseError，按降级纪律**整体待人工确认**（绝不基于残缺输入给出确定性结论）；
- 参数卡抽取：正则+槽位（加固方法/材料/胶粘剂指标/锚固深度/设计参数等），**每项带原文证据**；非原文子串的抽取结果丢弃并留痕（防幻觉双闸）。

### 5.2 规则引擎

4 条规则（R-ADH-001 胶粘剂等级分档区间比对 / R-ANCH-001 锚固需求下限筛查 / R-APP-001 先鉴定后加固存在性 / R-CONST-001 构造措施缺失型），三级判定（不符合/疑似/待人工确认，加 pass 共四态展示）：

- **status 门控先于一切数值判定**：规则引用的条款未核对 → 整体 needs_confirm；
- **判定口径按信息完备度设计**（误报 0 目标）：如 R-ANCH-001 采用"最有利假设需求下限"筛查——方案文档一般不提供间距/保护层等参数，核查层不虚构：低于严格下界才判不符合（可证），高于下限只判筛查通过并注明精确复算走验算层，输入缺失 → needs_confirm，绝不猜值；
- **宁缺勿错**：检查单自动建议只做"证据在场"筛查，绝不自动给"不符合"。

## 六、合成数据设计（基准含金量的来源）

### 6.1 合成方案生成器

`datagen/gen_plan.py`：python-docx 生成"加固方案"节选文档（检测鉴定结论/加固设计说明/材料要求/构造措施章节），**固定 seed=20261005**；docx zip 时间戳归一化 (1980,1,1) 使同 seed 两次运行 **sha256 逐字节一致**（可复现性的位级口径）。

### 6.2 真值语义（一次定清）

- 基线文档全合规（`clean_baseline: true`）+ 每份注入 1-N 处已知错误（与规则库 rule_id 一一对应）；
- 注入项记主期望 `expected_verdict`；评测按**文档全部非 pass 集合对账**——多报期望之外的问题算误报；
- 基准**现场生成**语料（不背产物）：生成后逐份 sha256 对 truth 校验，不一致计 issue 拒判——杜绝"产物在手、生成器悄悄漂移"的假绿。

### 6.3 双基准与门槛（双向锁死）

| 基准 | 指标 | 门槛 |
|---|---|---|
| 验算算例（14 例：规范公式手算回填+查表例，±0.5% 容差 + verdict 严格相等） | 通过率 | 100%（14/14） |
| 方案核查（6 份合成语料：基线+5 注入） | 检出率（规则实例） | 100%（7/7） |
| 方案核查 | **误报数** | **0** |
| 方案核查 | 判定准确率（主期望 verdict 严格相等） | 100%（7/7） |

门槛常量（1.0/0/1.0）在 bench 模块与测试**双向锁死**：指标不达 → 回修实现，**不放宽门槛**。`ssc bench` 一条命令复现双基准，CI 四矩阵常驻。

### 6.4 参数扫描位级锁定

随机参数网格（固定 seed=20261005 × 12 落点/模块 × 4 模块）输出 sha256 位级锁定（双跑一致+金标准哈希双保险），防实现漂移。配套 EOL 策略（`.gitattributes` eol=lf + CR 守门），防 Windows autocrlf 重写导致全新 clone 基准全挂。

## 七、质量守门体系

- **pytest 168 项**：schema 守门/门控/降级路径/基准/GUI（offscreen）/打包纪律/项目守门（含源码无个人路径、全离线 import 断言）+ 算例门槛 CLI 层守门、条款复核锚、EOL 字节级守门、版本单一来源；
- **CI 四矩阵**（3.12/3.13 × ubuntu-latest/windows-latest，windows/3.12 加装 gui）：install → pytest → selfcheck → bench → 脱敏 selftest/metadata 常驻；
- **打包红线断言**：构建后遍历 dist 全树——禁区成分（规范全文/渠道记录/合成产物/计算底稿）不入包，内嵌数据与仓库逐份对账，任一违反 exit 1；
- **脱敏发布门**：`tools/desensitize_scan.py` 扫描入仓树+产物本体（邮箱/个人标记/绝对路径/姊妹项目词），并自证（`--selftest` 阳性 4 + 阴性 4）与查提交元数据（`--mode metadata`，非 GitHub noreply 即红）；硬门全清（实录见 [plan/RELEASE-M7.md](RELEASE-M7.md) 与 [plan/RELEASE-M6.md](RELEASE-M6.md)）。

## 八、交付形态

- **CLI**：`ssc selfcheck/modules/calc/check/checklist/bench/report/gui` 全命令面，退出码语义=命令执行状态而非核查结论（核查完成即 0，结论看报告汇总行）；
- **GUI**：PySide6 四页签（验算表单/方案核查/检查单/报告），全部消费既有 API，与 CLI 不另起第二套行为；
- **exe**：PyInstaller onedir 双 exe（SSC.exe 图形界面 + ssc-cli.exe 控制台供无 Python 机器脚本化验证）；数据内嵌策略冻结分支（显式 > 环境变量 > 内嵌 > CWD 上溯），干净环境验证：中立目录+剥离 PATH 下五通路全过。
