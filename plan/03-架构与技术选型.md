## 一、总体分层架构

```mermaid
flowchart TB
    subgraph 交付层
        CLI[CLI: ssc]
        GUI[PySide6 桌面界面]
        EXE[PyInstaller exe]
        DOC[报告 docx 导出]
    end
    subgraph 应用编排层
        ORCH[流水线: 方案文件→参数卡→核查→报告]
        REG[验算模块注册表]
    end
    subgraph 核心引擎层（仅 stdlib，零依赖）
        FE[公式引擎<br/>条款-公式-符号表<br/>status 门控]
        RE[规则引擎<br/>三级判定+类目门控]
        CL[检查单引擎<br/>GB 55021 条目核对]
        VAL[合法性校验<br/>数值范围/量纲]
    end
    subgraph 解析层（optional deps，惰性导入）
        P1[docx 文本提取]
        P2[PDF 文本提取]
        P3[参数卡抽取<br/>规则优先：正则+槽位]
    end
    subgraph 数据层（JSON 入仓）
        KB[条款库<br/>编号/条号/要点/公式元数据/限值/出处/status]
        CASES[算例库<br/>真值+来源台账]
        RULES[核查规则库<br/>id/门控/判定/建议]
        SYN[合成方案生成器（固定 seed）]
    end
    CLI --> ORCH
    GUI --> ORCH
    CLI --> REG
    GUI --> REG
    ORCH --> FE & RE & CL
    REG --> FE
    P1 & P2 --> P3 --> RE
    FE --> KB
    RE --> RULES
    CL --> KB
    CASES --> FE
    SYN --> CASES
    DOC --> ORCH
```

分层纪律：
- **核心引擎层只 import stdlib**——公式、规则、检查单、数据读写全部零依赖，基准与 CI 不装任何第三方包即可跑；
- **解析层与交付层依赖全部 optional extras + 惰性导入**：缺依赖时抛"带安装提示"的友好异常，CLI 捕获降级退出（exit 2），绝不崩溃到 traceback；
- **依赖方向单向向下**：交付层→编排层→核心层→数据层；核心层不感知 GUI/CLI 的存在。

## 二、技术选型表

| 项 | 选型 | 理由 | 备选（否决理由） |
|---|---|---|---|
| 语言/版本 | Python ≥3.8（本机 3.8.8 唯一解释器） | 环境现实；CI 双版本 3.8/3.12 锁兼容 | 仅 3.12（放弃本机可跑性） |
| 桌面框架 | PySide6（LGPL） | 题目指定；Qt 官方绑定 | Tkinter（表现力不足）、wxPython（打包体积/资料少） |
| 公式编码 | **Python 函数注册 + 元数据 JSON**（非 DSL/表达式字符串） | 计算步骤可读可调试、可挂中间量；公式复杂（如二次受力应变滞后）用表达式引擎反而绕 | sympy（重依赖，破坏零依赖核心）、自造 DSL（解析成本>收益） |
| 数据存储 | JSON 文件（条款库/算例库/规则库） | 入仓可评审、diff 友好、零依赖 | SQLite（单机只读知识库无必要） |
| docx 读写 | python-docx | 事实标准；生成器/报告共用 | docxtpl（模板灵活性够但多一层概念） |
| PDF 文本 | pypdf（P1，纯文本提取够用） | 轻量、无系统依赖 | pdfplumber（重，P1 场景不需要版面分析） |
| 测试 | pytest | 标配；分批跑纪律 | unittest（写起来啰嗦） |
| 打包 | PyInstaller onedir（发布可议 onefile） | 题目要求 Windows exe | Nuitka（编译慢、生态坑） |
| CI | GitHub Actions：pytest + bench + 脱敏守门，ubuntu+windows × 3.8/3.12 | 干净环境证据链 | 只测开发机（ extras 缺失会静默漏，方法论实录教训） |

## 三、关键设计决策

### 3.1 条款-公式-符号表（公式引擎骨架）

- **条款库条目**（JSON）：`clause_id`（如 `GB50367-2013 §8.2` 形态，条号以核对后原文为准）、规范号、条号、要点摘录、公式编号、变量符号表（符号/含义/单位/合法范围）、限值、出处（渠道+定位）、`status`（待核对/已核对）。
- **公式编码**：每个验算模块一个 Python 函数，`@register_calc("cfrp_beam_flexure")` 注册；函数体内逐步骤计算并把每步（公式编号、符号、数值、单位、依据 clause_id）追加到 `steps` 列表；最终输出承载力值/效应比/三级结论。
- **status 门控（FR-A7）**：注册装饰器声明所需条款集合；引擎在计算入口校验全部条款 `status==已核对`，否则 `ClauseNotVerifiedError`（含"先按 05 的核对流程入库"提示）。骨架阶段 4 个模块**故意不实现计算体**，条款 status 也不齐——门控本身可测。
- **单位制**：全 SI 内部单位（N、mm、MPa），参数卡字段带单位标注，校验器按符号表范围拒绝越界值。

### 3.2 规则引擎（方案核查骨架）

- 规则 JSON：`id / 名称 / 类目门控(only_if_keywords) / check_type(param_range|param_required|checklist|consistency) / 目标参数 / 判定op与限值 / 依据clause_id / 级别(不符合|疑似|待人工确认) / 建议文案`。
- **三级判定**：`fail`（确定性不符）/ `suspicious`（疑似，置信不足）/ `needs_confirm`（待人工确认）——多值/低置信度**不硬判**为 fail。
- **类目门控**：每条规则带互斥门控关键词，门控对**全部** check_type 生效（含 checklist/conditional 分支——系列项目实测踩坑点）。
- **证据链**：每条结论附方案原文摘录，摘录非原文子串即丢弃该条（防解析幻觉）。

### 3.3 中间表示：参数卡

- 验算参数卡（`CalcInput` 子类，dataclass）：字段=符号+值+单位+来源（手工输入），JSON 可序列化（CLI 与 GUI 共用同一份输入文件格式）；
- 方案参数卡（`PlanParamCard`）：加固方法清单/材料等级/胶粘剂性能指标/锚固深度/卸载要求/裂缝修补方式，每项带 `{值, 单位, 置信度, 证据{页码/段落/原文摘录}}`；
- 协同比对、核查、报告全部消费参数卡，两侧文档差异问题归约为结构化对齐（方法论阶段 2）。

### 3.4 依赖分层（extras）

| extra | 包 | 用途 | 未装时行为 |
|---|---|---|---|
| （默认，零依赖） | — | 公式引擎/规则引擎/检查单/CLI/基准（规则通路） | 全功能可用 |
| `gui` | PySide6 | 桌面界面 | `ssc gui` 友好提示安装命令后退出 |
| `report` | python-docx | docx 导出 | `ssc report` 降级提示 |
| `parse` | python-docx, pypdf | 方案文本提取 | `ssc check` 提示装 `.[parse]` |
| `dev` | pytest | 测试 | — |
| `package` | pyinstaller | exe 打包 | — |

纪律：**extras 必须覆盖运行期与测试期真实 import**（含框架隐式依赖，如 docx 生成无隐式坑、PySide6 无，但入库前用干净环境验证 + 守门测试断言 extras 覆盖 import 面——方法论阶段 6/7 实录教训）。

### 3.5 为什么本项目无 LLM 兜底（与系列方法论差异）

题目要求全离线 + 确定性可评测；验算是纯公式、方案参数是"数值+等级词表"强格式，规则优先解析 + 合法性校验 + `待人工确认`级别足以兜住，引入 LLM 反而破坏"误报 0"与离线约束。防幻觉三件套中保留两条确定性手段：摘录必须是原文子串、数值合法性范围校验。

## 六、风险与对策（架构相关）

| 风险 | 对策 |
|---|---|
| 3.8 语法兼容回退（AI 写代码易用新语法） | CI 3.8 矩阵常驻；`python_requires` 硬门 |
| 公式条款号/章节归属核对错误 | status 门控 + 05 的核对流程（原文为准，不得自证） |
| PySide6 在 3.8 的可用版本上限（约 6.6/6.7，需实测） | M5 前置 spike；extras 不锁死小版本，锁定策略在 06 决策表记录 |
| docx 解析格式多样性（方案书排版差异大） | 规则优先+槽位+置信度；解析失败整卡降级为 needs_confirm 而非误判 |
| 版权风险 | 全文不入仓；条目=要点+短摘录+出处（data/README 台账纪律） |
