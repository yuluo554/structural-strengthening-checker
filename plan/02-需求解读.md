## 一、用户与使用场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 结构设计/加固设计人员 | 快速复核加固验算（对照商业软件结果） | 计算过程透明、逐条挂条款号 |
| 施工图审查/咨询人员 | 审查加固方案文本 | 关键参数不漏查，问题挂规范出处 |
| 高校师生（教学/课程设计/备考） | 学习加固规范的公式与应用 | 公式+条款+算例一体，可复现 |
| 既有建筑改造管理方 | GB 55021-2021 强制条款自查 | 检查单式逐项核对留痕 |

## 二、痛点 → 能力转译表

| # | 行业痛点（来自 01 §一） | 转译为产品能力 | 对应 FR |
|---|---|---|---|
| 1 | 商业加固模块闭源收费、计算过程不开放 | 开源公式引擎：输入参数卡 → 中间步骤 → 结论，逐步骤可读，结论逐条挂条款号+公式编号 | FR-A 系列 |
| 2 | 方案审查靠人工比对，材料等级/胶粘剂性能/锚固深度/构造措施/卸载要求漏查错查 | 方案文本解析为参数卡 + 规则引擎限值核查，三级判定（不符合/疑似/待人工确认），每条挂条款出处与原文摘录 | FR-B 系列 |
| 3 | GB 55021-2021 全文强制后无系统化符合性自查工具 | 强制条款要点化检查单，交互式逐项核对，输出符合性清单 | FR-C 系列 |
| 4 | 验算与核查结果缺乏可信的证据链 | 验算书/核查报告 docx 导出：证据链（原文摘录+条款号）+ 签署栏 + 免责声明 | FR-D 系列 |
| 5 | 工具可信度无法验证 | 内置零 API 依赖基准：规范算例真值 + 合成方案植入已知错误，指标公开进 README | FR-E 系列 |

## 四、NFR 非功能需求

| 类别 | 要求 |
|---|---|
| 平台 | Windows 10/11 x64 为第一目标（打包 exe）；核心层跨平台（CI 覆盖 ubuntu） |
| Python | 本机唯一解释器 3.8.8 → `requires-python>=3.8`，语法限 3.8（无 `X|Y` 运行时注解、无 match） |
| 依赖 | 核心层（公式/规则/检查单/数据层）仅 stdlib；PySide6/python-docx/pypdf 全部 optional extras + 惰性导入 |
| 可复现 | 基准零 API 依赖、固定 seed、位级锁定；无出处数值不得作真值 |
| 中文 | 源码 UTF-8；控制台输出用 `py -X utf8` 约定；docx/路径全中文兼容 |
| 确定性 | 数值结论只来自确定性计算，绝不由生成式组件产生 |
| 合规 | 规范全文（版权物）不入仓；条目=要点+短摘录+出处；免责声明强制 |

## 五、边界与非目标（防 scope 失控，源自 01 §六，逐条固化）

1. **不做**任何图像/点云/视频输入（裂缝识别、实景建模等识图路线明确排除）；
2. **不做**整体结构有限元分析（限构件级验算）；
3. 砌体/钢结构加固**首期不做**（版本扩展项，规则引擎与参数卡 schema 预留扩展位）；
4. 不引入 LLM/API——全离线、确定性、可评测（与系列前七项目的方法论差异，LLM 兜底环节以"规则优先+合法性校验+待人工确认级别"替代）；
5. 真实工程数据**不采集不使用**（算例=规范例题+公开教材+合成方案）；
6. **免责红线**：辅助验算与核查定位，不替代正式设计、施工图审查与竣工验收；报告强制免责声明；
7. **条文纪律**：公式、限值、指标全部以规范原文核对后入库（挂编号+条号+渠道+status）；查不到原文显式标"待核对"，不得进入计算与结论；
8. **品牌隔离**：不复制姊妹项目代码；文档不提其余项目业务领域。
